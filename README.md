# Enterprise Private GPT — локальный RAG-ассистент

## Запуск
Colab: откройте notebook, выберите GPU T4, выполните ячейки сверху вниз.
Локально: python -m venv venv && pip install -r requirements.txt, затем запустите код из ноутбука (нужна GPU от ~10 ГБ VRAM или CPU + меньшая модель).

## Архитектура
Документы (PDF/TXT) → RecursiveCharacterTextSplitter (500/100) → multilingual-e5-base → ChromaDB (cosine) → top-K поиск → промпт с контекстом → Qwen3-4B → ответ в Gradio.

## Выводы
Выбор моделей. LLM — Qwen3-4B: хорошо понимает русский, помещается в 16 ГБ T4 в fp16 (8 ГБ), поддерживает следование инструкциям. Эмбеддинги — multilingual-e5-base: мультиязычная модель с хорошим качеством поиска на русском при небольшом размере (280M параметров); 
Трудности локального развёртывания по сравнению с облачными API.

Память: модели 7B+ не помещаются в 16 ГБ без квантизации (4-bit/GGUF), что снижает качество.
Скорость: генерация на T4 заметно медленнее облачных API; latency растёт вместе с top-K (длиннее контекст).
Галлюцинации и следование промпту: малые модели иногда отвечают «из головы» при слабом контексте или плохо отказываются отвечать вне базы; помогает низкая температура, строгий промпт, порог по расстоянию при поиске.
Качество поиска: чанки могут разрезать мысль; важно подбирать chunk_size/overlap.
Надёжность и защита данных. Архитектура защищает данные, только если всё (LLM, эмбеддинги, БД, интерфейс) работает внутри контура компании: данные не уходят во внешние API. Но надёжность не абсолютная: в Colab виртуальная машина остаётся в облаке Google, share=True в Gradio открывает публичную ссылку; нужны разграничение доступа к документам (ACL по пользователям), аудит логов, защита от prompt injection из самих документов, и модель всё равно может «проговориться» или выдать ответ вне контекста. Поэтому настоящую защиту даёт развёртывание на собственном сервере без внешнего доступа + контроль доступа, а не сам факт использования RAG.
